## 1. 概述

### 1.1 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合检索和生成的 AI 架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                      RAG 架构                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐              │
│  │ Document │───▶│  Chunker │───▶│ Embedding    │              │
│  │ (文档)    │    │ (分块)    │    │ Model        │              │
│  └──────────┘    └──────────┘    └──────┬───────┘              │
│                                          │                       │
│                                          ▼                       │
│                                   ┌──────────────┐             │
│                                   │ VectorStore  │             │
│                                   │ (向量存储)    │             │
│                                   └──────┬───────┘             │
│                                          │                       │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐              │
│  │ Response │◀───│  LLM     │◀───│  Retriever   │              │
│  │ (回复)    │    │ (生成)    │    │ (检索)       │              │
│  └──────────┘    └──────────┘    └──────────────┘              │
│                                          ▲                       │
│                                          │                       │
│                                   ┌──────────────┐              │
│                                   │ User Query   │              │
│                                   │ (用户查询)    │              │
│                                   └──────────────┘              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 RAG 工作流程

1. **索引阶段**（离线）：
   - 加载文档 → 分块 → Embedding → 存入 VectorStore

2. **查询阶段**（在线）：
   - 用户查询 → Embedding → 相似度检索 → 上下文 → LLM 生成

## 2. Embedding 嵌入模型

### 2.1 什么是 Embedding

Embedding 是将文本转换为固定长度向量的技术，相似的文本会有相似的向量：

```
文本 ──▶ Embedding Model ──▶ 向量

"你好"      ──▶  [0.12, -0.34, 0.56, ...]  (1536维)
"hello"    ──▶  [0.11, -0.35, 0.55, ...]  (相似！)
"计算机"   ──▶  [0.89, 0.12, -0.45, ...]  (不同)
```

### 2.2 Eino Embedder 接口

```go
// Embedder 接口定义
type Embedder interface {
    // EmbedStrings 将多个文本转换为向量
    EmbedStrings(ctx context.Context, texts []string) ([][]float32, error)
}

// 接口位置：github.com/cloudwego/eino/embeddings
```

### 2.3 OpenAI Embedding 示例

**功能说明**：使用 OpenAI 的 text-embedding-3-small 模型生成文本向量

**关键组件**：
- `openai.Embedder`: OpenAI Embedding 实现
- `chatbot.Message`: 用于构建带上下文的提示

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/cloudwego/eino/embeddings"
	"github.com/cloudwego/eino/embeddings/openai"
)

// OpenAI Embedding 使用示例
// 参考：Eino 示例项目 embeddings/openai/

func main() {
	ctx := context.Background()

	// 1. 创建 OpenAI Embedder
	// 注意：也可以使用环境变量 OPENAI_API_KEY
	embedder, err := openai.NewEmbedder(ctx, &openai.EmbedderConfig{
		APIKey: "your-api-key",
		Model:  openai.EmbedModelTextEmbedding3Small, // 1536 维
	})
	if err != nil {
		log.Fatalf("创建 Embedder 失败: %v", err)
	}

	// 2. 嵌入单个或多个文本
	texts := []string{
		"什么是人工智能？",
		"机器学习是 AI 的一个分支",
		"今天天气真好",
	}

	vectors, err := embedder.EmbedStrings(ctx, texts)
	if err != nil {
		log.Fatalf("生成 Embedding 失败: %v", err)
	}

	// 3. 查看结果
	fmt.Printf("嵌入 %d 个文本，每个向量 %d 维\n", len(texts), len(vectors[0]))
	fmt.Printf("第一个向量前 5 维: %v\n", vectors[0][:5])
}
```

**运行方式**：
```bash
# 设置 API Key
export OPENAI_API_KEY="your-key"

# 运行
cd embeddings/openai
go run main.go
```

**预期输出**：
```
嵌入 3 个文本，每个向量 1536 维
第一个向量前 5 维: [0.019 -0.002 0.031 0.002 -0.012]
```

## 3. VectorStore 向量数据库

### 3.1 VectorStore 接口

```go
// VectorStore 接口定义
// 位于：github.com/cloudwego/eino/vectorstore

type VectorStore interface {
    // Store 保存文档块到向量数据库
    Store(ctx context.Context, chunks []*Chunk) error

    // Retrieve 根据查询向量检索最相似的 k 个文档块
    Retrieve(ctx context.Context, query string, k int) ([]*Chunk, error)

    // SimilaritySearch 另一种检索方式
    SimilaritySearch(ctx context.Context, query string, k int) ([]*Chunk, error)
}

// Chunk 定义
type Chunk struct {
    ID       string
    Content  string
    MetaData map[string]any
    Score    float32 // 相似度分数（检索后填充）
}
```

### 3.2 Chroma 向量数据库示例

**功能说明**：使用 Chroma（本地向量数据库）存储和检索文档

**关键组件**：
- `chroma.NewStore`: 创建 Chroma Store 实例
- `embeddings.Embedder`: 用于查询时生成向量

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/cloudwego/eino/embeddings/openai"
	"github.com/cloudwego/eino/schema"
	"github.com/cloudwego/eino/vectorstore/chroma"
)

// Chroma VectorStore 使用示例
// Chroma 是一个轻量级的本地向量数据库，适合开发和测试

func main() {
	ctx := context.Background()

	// 1. 创建 Embedder
	embedder, err := openai.NewEmbedder(ctx, &openai.EmbedderConfig{
		APIKey: "your-api-key",
		Model:  openai.EmbedModelTextEmbedding3Small,
	})
	if err != nil {
		log.Fatalf("创建 Embedder 失败: %v", err)
	}

	// 2. 创建 Chroma Store
	store, err := chroma.NewStore(ctx, &chroma.StoreConfig{
		Embedder: embedder,
		CollectionName: "my-documents",
		Path: "./chroma_db", // 本地存储路径
	})
	if err != nil {
		log.Fatalf("创建 Chroma Store 失败: %v", err)
	}
	defer store.Close()

	// 3. 准备文档块
	chunks := []*schema.Text{
		{
			ID:   "doc1",
			Content: "Eino 是一个由字节跳动开发的 AI 应用框架",
			Metadata: map[string]any{"source": "官网"},
		},
		{
			ID:   "doc2",
			Content: "Go 语言以其高效的并发模型著称",
			Metadata: map[string]any{"source": "维基百科"},
		},
		{
			ID:   "doc3",
			Content: "RAG 结合了检索和生成两种技术",
			Metadata: map[string]any{"source": "技术博客"},
		},
	}

	// 4. 存储文档
	err = store.Store(ctx, chunks)
	if err != nil {
		log.Fatalf("存储文档失败: %v", err)
	}
	fmt.Println("文档存储成功！")

	// 5. 检索相似文档
	results, err := store.Retrieve(ctx, "什么是 Eino 框架？", 2)
	if err != nil {
		log.Fatalf("检索失败: %v", err)
	}

	fmt.Printf("\n检索到 %d 个相关文档：\n", len(results))
	for i, doc := range results {
		fmt.Printf("%d. [%s] %s (相似度: %.4f)\n",
			i+1, doc.ID, doc.Content, doc.Score)
	}
}
```

**运行方式**：
```bash
cd vectorstore/chroma
go run main.go
```

**预期输出**：
```
文档存储成功！

检索到 2 个相关文档：
1. [doc1] Eino 是一个由字节跳动开发的 AI 应用框架 (相似度: 0.8923)
2. [doc3] RAG 结合了检索和生成两种技术 (相似度: 0.6541)
```

### 3.4 向量数据库选型指南

## 4. Retriever 检索器

// Retriever 接口定义

type Retriever interface {

### 4.2 基础 VectorRetriever

**功能说明**：使用向量数据库进行基础相似度检索

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/cloudwego/eino/compose"
	"github.com/cloudwego/eino/embeddings/openai"
	"github.com/cloudwego/eino/schema"
	"github.com/cloudwego/eino/vectorstore/chroma"
)

// 使用 Eino Compose 创建基础 Retriever

func main() {
	ctx := context.Background()

	// 1. 初始化组件
	embedder, _ := openai.NewEmbedder(ctx, &openai.EmbedderConfig{
		APIKey: "your-api-key",
		Model:  openai.EmbedModelTextEmbedding3Small,
	})

	store, _ := chroma.NewStore(ctx, &chroma.StoreConfig{
		Embedder:      embedder,
		CollectionName: "knowledge-base",
		Path:          "./chroma_db",
	})

	// 2. 创建 Retriever
	retriever := compose.NewRetriever(
		compose.WithRetrieverStore(store),
		compose.WithTopK(3), // 返回 Top 3 结果
	)

	// 3. 检索
	docs, err := retriever.Retrieve(ctx, "Eino 框架的特点")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("检索到 %d 个结果：\n", len(docs))
	for _, doc := range docs {
		fmt.Printf("- %s\n", doc.Content)
	}
}
```

### 4.3 MultiQuery Retriever

**功能说明**：通过 LLM 生成多个查询变体来扩展召回

```
用户查询 "Eino 是什么"
      │
      ▼
┌─────────────────┐
│ LLM 生成变体     │
├─────────────────┤
│ 1. Eino 框架介绍 │
│ 2. Eino 怎么用   │
│ 3. Eino vs LangChain │
└─────────────────┘
      │
      ▼
┌─────────────────┐
│ 并行向量检索     │
└─────────────────┘
      │
      ▼
┌─────────────────┐
│ 结果去重合并     │
└─────────────────┘
```

```go
package main

import (
	"context"
	"fmt"

	"github.com/cloudwego/eino/agent/retriever"
	"github.com/cloudwego/eino/chatbot/openai"
	"github.com/cloudwego/eino/compose"
)

// MultiQuery Retriever 示例
// 通过生成多个查询变体提高召回率

func main() {
	ctx := context.Background()

	// 1. 创建 ChatModel 用于生成查询变体
	model, _ := openai.NewChatModel(ctx, &openai.ChatModelConfig{
		APIKey: "your-api-key",
		Model:  "gpt-4o-mini",
	})

	// 2. 创建基础 Retriever
	baseRetriever := compose.NewRetriever(/* ... */)

	// 3. 创建 MultiQuery Retriever
	mqRetriever := retriever.NewMultiQuery(
		retriever.WithQueryGenerator(model),
		retriever.WithBaseRetriever(baseRetriever),
		retriever.WithNumQueries(5), // 生成 5 个变体
	)

	// 4. 检索时会自动生成多个查询并合并结果
	docs, _ := mqRetriever.Retrieve(ctx, "字节跳动的 AI 框架")
	fmt.Printf("通过 MultiQuery 检索到 %d 个文档\n", len(docs))
}
```

### 4.4 Ensemble Retriever

**功能说明**：组合多个检索器的结果，通过加权融合得到最终结果

```go
package main

import (
	"context"

	"github.com/cloudwego/eino/agent/retriever"
)

// Ensemble Retriever 示例
// 融合多种检索策略的结果

func main() {
	ctx := context.Background()

	// 创建多个检索器
	retriever1 := createVectorRetriever() // 向量检索
	retriever2 := createBM25Retriever()   // 关键词检索
	retriever3 := createHybridRetriever() // 混合检索

	// 创建 Ensemble Retriever
	ensemble := retriever.NewEnsemble(
		retriever.WithRetrievers(retriever1, retriever2, retriever3),
		retriever.WithWeights([]float64{0.5, 0.2, 0.3}), // 加权融合
		retriever.WithTopK(10),
	)

	docs, _ := ensemble.Retrieve(ctx, "Eino 框架")
	// 融合后的检索结果
}
```

### 4.5 Router Retriever

**功能说明**：根据查询类型路由到不同的检索器

```go
package main

import (
	"context"

	"github.com/cloudwego/eino/agent/retriever"
)

// Router Retriever 示例
// 根据查询内容自动选择合适的检索器

func main() {
	ctx := context.Background()

	// 创建针对不同领域的检索器
	codeRetriever := createCodeRetriever()     // 代码相关
	docRetriever := createDocumentationRetriever() // 文档相关
	qaRetriever := createQARetriever()          // 问答相关

	// 创建 Router
	router := retriever.NewRouter(
		retriever.WithRouters(
			&retriever.RouterConfig{
				Name:        "代码检索",
				Description: "用于编程、代码相关问题",
				Retriever:   codeRetriever,
				Filter: func(query string) bool {
					// 简单关键词匹配
					keywords := []string{"代码", "函数", "bug", "编程", "code"}
					for _, kw := range keywords {
						if contains(query, kw) {
							return true
						}
					}
					return false
				},
			},
			// ... 更多路由规则
		},
		retriever.WithDefaultRetriever(docRetriever),
	)

	// 自动路由检索
	docs, _ := router.Retrieve(ctx, "如何修复这个 bug")
}
```

### 5.2 使用 Eino Graph 构建 RAG

**功能说明**：使用 Eino Compose 的 Graph 构建完整的 RAG 工作流

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/cloudwego/eino/chatbot/openai"
	"github.com/cloudwego/eino/compose"
	"github.com/cloudwego/eino/compose/graph"
	"github.com/cloudwego/eino/embeddings/openai"
	"github.com/cloudwego/eino/schema"
	"github.com/cloudwego/eino/vectorstore/chroma"
)

// RAG Graph 工作流示例
// 参考：Eino 示例项目 compose/graph/rag/

// 定义输入输出类型
type RAGInput struct {
	Query string `json:"query"`
}

type RAGOutput struct {
	Answer  string   `json:"answer"`
	Sources []string `json:"sources"`
}

// RAG 工作流
func buildRAGGraph(ctx context.Context) (*graph.Graph, error) {
	// 1. 初始化组件
	embedder, err := openai.NewEmbedder(ctx, &openai.EmbedderConfig{
		APIKey: "your-api-key",
		Model:  openai.EmbedModelTextEmbedding3Small,
	})
	if err != nil {
		return nil, err
	}

	chatModel, err := openai.NewChatModel(ctx, &openai.ChatModelConfig{
		APIKey: "your-api-key",
		Model:  "gpt-4o-mini",
	})
	if err != nil {
		return nil, err
	}

	store, err := chroma.NewStore(ctx, &chroma.StoreConfig{
		Embedder:      embedder,
		CollectionName: "knowledge-base",
		Path:          "./chroma_db",
	})
	if err != nil {
		return nil, err
	}

	// 2. 创建检索节点
	retriever := compose.NewRetriever(
		compose.WithRetrieverStore(store),
		compose.WithTopK(5),
	)

	// 3. 创建生成节点
	generator := compose.NewChatModelNode(
		compose.WithChatModel(chatModel),
	)

	// 4. 构建 Graph
	g := compose.NewGraph[string, string]()

	// 添加节点
	g.AddNode("retriever", retriever)
	g.AddNode("generator", generator)

	// 添加边：检索 -> 生成
	g.AddEdge("retriever", "generator")

	// 设置起点和终点
	g.SetStart(func(ctx context.Context, input string) (string, error) {
		docs, err := retriever.Retrieve(ctx, input)
		if err != nil {
			return "", err
		}
		// 构建上下文
		context := buildContext(docs)
		return context, nil
	})

	g.SetEnd(func(ctx context.Context, output string) (string, error) {
		return output, nil
	})

	return g.Compile(ctx)
}

// 构建上下文字符串
func buildContext(docs []*schema.Text) string {
	var context string
	for i, doc := range docs {
		context += fmt.Sprintf("\n[%d] %s", i+1, doc.Content)
	}
	return context
}

// 使用 RAG
func main() {
	ctx := context.Background()

	g, err := buildRAGGraph(ctx)
	if err != nil {
		log.Fatal(err)
	}

	// 执行查询
	result, err := g.Invoke(ctx, "Eino 框架有什么特点？")
	if err != nil {
		log.Fatal(err)
	}

	fmt.Println("RAG 回答:", result)
}
```

### 5.3 带历史记忆的 RAG

**功能说明**：在 RAG 中集成 Memory，支持多轮对话

```go
package main

import (
	"context"
	"log"

	"github.com/cloudwego/eino/chatbot"
	"github.com/cloudwego/eino/memory"
	"github.com/cloudwego/eino/memory/buffer"
	"github.com/cloudwego/eino/compose"
)

// 带记忆的 RAG 示例

func main() {
	ctx := context.Background()

	// 1. 创建 Memory（使用 Buffer Memory）
	mem := buffer.NewBufferMemory(
		buffer.WithMaxMessages(10), // 保留最近 10 条消息
	)

	// 2. 创建带记忆的 RAG Chain
	chain := compose.NewChain[string, string](
		compose.WithChainNodes(
			compose.NewChatModelNode(/* model */),
		),
		compose.WithChainInput(func(ctx context.Context, input string) (string, error) {
			// 获取历史对话
			history, _ := mem.GetMessages(ctx)
			// 追加当前查询
			history = append(history, chatbot.UserMessage(input))
			// 检索相关文档
			docs, _ := retrieveDocs(ctx, input)
			// 构建带上下文的提示
			prompt := buildPromptWithContext(history, docs)
			return prompt, nil
		}),
		compose.WithChainOutput(func(ctx context.Context, output string) (string, error) {
			// 保存助手回复到记忆
			mem.SaveMessages(ctx, chatbot.AssistantMessage(output))
			return output, nil
		}),
	)

	// 3. 多轮对话
	chain.Run(ctx, "Eino 是什么？")
	chain.Run(ctx, "它支持哪些模型？") // 上下文包含之前的对话
}

// 辅助函数
func retrieveDocs(ctx context.Context, query string) ([]string, error) {
	// 检索逻辑
	return []string{"Eino 是字节跳动的 AI 框架"}, nil
}

func buildPromptWithContext(history []chatbot.Message, docs []string) string {
	var prompt string
	// 添加文档上下文
	if len(docs) > 0 {
		prompt += "参考以下文档：\n"
		for _, doc := range docs {
			prompt += "- " + doc + "\n"
		}
	}
	// 添加对话历史
	prompt += "\n对话历史：\n"
	for _, msg := range history {
		prompt += msg.String() + "\n"
	}
	return prompt
}
```

		fmt.Print(chunk.Content)
	}

## 7. 常见问题

### Q1: 检索结果完全不相关

**可能原因**：
- Embedding 模型与文档语言不匹配
- chunk_size 设置不当（太大或太小）
- 向量数据库未正确连接

**排查方法**：
1. 检查 Embedding 模型是否支持文档语言
2. 查看检索到的文档内容是否正确存入
3. 测试 Embedding 是否正常工作

**解决方案**：
- 更换为支持对应语言的 Embedding 模型
- 调整 chunk_size 参数
- 重新导入文档到向量数据库

### Q2: 检索结果太少

**可能原因**：
- top_k 值设置过小
- 相似度阈值设置过高

**解决方案**：
```go
retriever := compose.NewRetriever(
    compose.WithRetrieverStore(store),
    compose.WithTopK(10), // 增加返回数量
)
```

### Q3: 检索速度慢

**可能原因**：
- 向量维度太高
- 数据量太大
- 网络延迟（云数据库）

**解决方案**：
- 使用维度更低的 Embedding 模型（如 text-embedding-3-small）
- 添加索引优化
- 使用本地向量数据库

### Q4: 如何处理中文检索？

**解决方案**：
1. 使用支持中文的 Embedding 模型：
   - multilingual-e5-large (Cohere)
   - m3e-base (本地)
   - text-embedding-3-small (OpenAI，中文一般)

2. 优化中文分词：
```go
// 使用中文分词器优化 chunk
import "github.com/go-ego/gse"

segmenter := gse.NewSegmenter()
segments := segmenter.Segment([]byte(document))
words := seg.Segment()
```

### Q5: 向量维度不匹配

**问题**：创建 Store 时维度与 Embedder 输出不匹配

**解决方案**：
```go
// 确保 Embedder 和 VectorStore 使用一致的配置
embedder, _ := openai.NewEmbedder(ctx, &openai.EmbedderConfig{
    Model: openai.EmbedModelTextEmbedding3Small, // 1536 维
})

store, _ := chroma.NewStore(ctx, &chroma.StoreConfig{
    Embedder:  embedder,
    Dimension: 1536, // 必须与 Embedder 输出一致
})
```
