## 1. Workflow 高级工作流

### 1.1 Workflow vs Graph 对比

| 特性 | Workflow | Graph |
|------|----------|-------|
| 依赖声明 | 声明式（通过 output 字段） | 隐式（按节点顺序） |
| 字段映射 | 支持 `From` 指定数据来源 | 手动处理 |
| 静态值 | 支持 `Value` 设置默认值 | 不支持 |
| 使用场景 | 复杂的数据转换和依赖 | 简单的线性/条件流程 |

### 1.2 声明式节点依赖

Workflow 的核心优势在于声明式依赖管理：

```go
// 节点 A、B 可以并行执行，因为它们不依赖任何节点
nodeA := workflow.NewNode(
    "node_a",
    myFuncA,
    workflow.WithOutput("result", "result_a"), // 显式指定输出
)

nodeB := workflow.NewNode(
    "node_b",
    myFuncB,
    workflow.WithOutput("result", "result_b"),
)

// 节点 C 依赖 A 和 B 的结果
nodeC := workflow.NewNode(
    "node_c",
    myFuncC,
    workflow.WithInput("a_result", "result_a"), // 从 A 获取
    workflow.WithInput("b_result", "result_b"), // 从 B 获取
    workflow.WithOutput("result", "result_c"),
)

// 节点 D 依赖 C 的结果
nodeD := workflow.NewNode(
    "node_d",
    myFuncD,
    workflow.WithInput("c_result", "result_c"),
)
```

### 1.3 字段映射详解

```go
// From 指定数据来源
workflow.WithInput("target_field", "source_field")

// 使用点号访问嵌套字段
workflow.WithInput("user.name", "input.user_name")

// 支持多个输入字段映射
workflow.NewNode(
    "process",
    processor,
    workflow.WithInput("id", "user_id"),
    workflow.WithInput("name", "user_name"),
    workflow.WithInput("email", "user_email"),
)

// 静态值设置（不依赖上游输出）
workflow.WithStaticValue("config", map[string]any{
    "timeout": 30,
    "retries": 3,
})

// 静态值可以被下游节点引用
workflow.WithInput("settings", "config")
```

### 1.4 完整的 Workflow 示例

```go
func BuildUserWorkflow(userFunc, validateFunc, notifyFunc func(ctx context.Context) (any, error)) (*workflow.WorkFlow, error) {
    wf := workflow.NewWorkFlow()

    // 节点1：获取用户信息（输入为 workflow 的 input）
    getUser := workflow.NewNode(
        "get_user",
        userFunc,
        workflow.WithInput("req", "input"),     // 从工作流输入获取
        workflow.WithOutput("user", "user_data"),
    )

    // 节点2：验证用户（依赖 getUser）
    validate := workflow.NewNode(
        "validate",
        validateFunc,
        workflow.WithInput("user", "user_data"), // 从 getUser 获取
        workflow.WithOutput("valid", "is_valid"),
        workflow.WithOutput("reason", "reject_reason"),
    )

    // 节点3：发送通知（依赖 validate）
    notify := workflow.NewNode(
        "notify",
        notifyFunc,
        workflow.WithInput("valid", "is_valid"),
        workflow.WithInput("reason", "reject_reason"),
    )

    return wf, nil
}
```

### 1.5 条件分支

虽然 Workflow 本身是声明式的，但可以结合条件逻辑实现分支：

```go
// 使用 filter 或 pre 处理实现条件
workflow.NewNode(
    "process",
    func(ctx context.Context, input any) (any, error) {
        if needsSpecialHandling(input) {
            return specialHandler(ctx, input)
        }
        return normalHandler(ctx, input)
    },
    workflow.WithOutput("result", "processed"),
)
```

## 2. BatchNode 并发批处理

### 2.1 BatchNode 概述

BatchNode 用于批量处理数据，支持：
- 并发控制（限制同时处理的数量）
- 中断恢复（处理中断后从断点继续）
- 结果收集

### 2.2 核心配置

```go
import "github.com/cloudwego/eino/compose/composeutils/batch"

// 创建批处理节点
batch.NewBatchNode(
    batch.WithConcurrency(10),                    // 最大并发数
    batch.WithMaxBatchSize(100),                  // 每批最大数量
    batch.WithBufferSize(200),                    // 输入缓冲区大小
    batch.WithName("my_batch"),                   // 节点名称
)
```

### 2.3 批处理函数签名

```go
// 单条处理函数
type ItemHandler[Item any, Result any] func(ctx context.Context, item Item) (Result, error)

// 批量处理函数（推荐，更高效）
type BatchHandler[Item any, Result any] func(ctx context.Context, items []Item) ([]Result, error)

// 两种方式的区别：
// - ItemHandler: 每次处理一条，适合独立任务
// - BatchHandler: 每次处理一批，适合可以批处理的场景（如批量 API 调用）
```

### 2.4 实际使用示例

```go
func BatchProcessImages(ctx context.Context, urls []string) ([]string, error) {
    // 定义处理函数
    processFn := func(ctx context.Context, items []string) ([]string, error) {
        results := make([]string, 0, len(items))
        for _, url := range items {
            result, err := downloadAndProcess(ctx, url)
            if err != nil {
                return nil, fmt.Errorf("处理 %s 失败: %w", url, err)
            }
            results = append(results, result)
        }
        return results, nil
    }

    // 创建批处理节点
    batchNode := batch.NewBatchNode(
        batch.WithName("image_processor"),
        batch.WithConcurrency(5),      // 最多 5 个并发
        batch.WithMaxBatchSize(10),    // 每批 10 个
        batch.WithBufferSize(50),      // 缓冲区 50
        batch.WithHandler(processFn),
    )

    // 收集结果
    allResults := make([]string, 0)
    for _, url := range urls {
        result, err := batchNode.Invoke(ctx, url)
        if err != nil {
            return nil, err
        }
        allResults = append(allResults, result.(string))
    }

    return allResults, nil
}
```

### 2.5 中断恢复机制

BatchNode 支持在处理过程中中断，并在恢复后从断点继续：

```go
// 创建带状态的批处理节点
batchNode, err := batch.NewBatchNode(
    batch.WithName(" resumable_processor"),
    batch.WithConcurrency(3),
    batch.WithHandler(processFn),
)

// 第一阶段：处理并中断
func ProcessWithInterrupt(ctx context.Context) error {
    // 模拟处理过程
    for i := 0; i < 100; i++ {
        _, err := batchNode.Invoke(ctx, i)
        if err == compose.ErrInterrupt {
            // 中断发生，保存状态
            SaveCheckpoint(ctx, batchNode.GetState())
            return err
        }
        if err != nil {
            return err
        }
    }
    return nil
}

// 第二阶段：从断点恢复
func ResumeFromCheckpoint(ctx context.Context) error {
    state := LoadCheckpoint()
    batchNode.SetState(state)

    // 继续处理
    for {
        _, err := batchNode.Invoke(ctx, GetNextItem())
        if err == compose.ErrStop {
            break // 完成
        }
        if err != nil {
            return err
        }
    }
    return nil
}
```

## 3. Multi-Agent 多 Agent 协作

### 3.1 多 Agent 模式概述

```
┌─────────────────────────────────────────────────────────┐
│                    Multi-Agent 系统                      │
│                                                         │
│   ┌─────────┐    ┌─────────┐    ┌─────────┐             │
│   │ Agent A │    │ Agent B │    │ Agent C │             │
│   │ (规划)  │───▶│ (执行)  │───▶│ (验证)  │             │
│   └─────────┘    └─────────┘    └─────────┘             │
│        │              │              │                   │
│        └──────────────┴──────────────┘                  │
│                     │                                   │
│              ┌──────┴──────┐                            │
│              │  Supervisor │  (监督者)                   │
│              │  - 协调 Agent                             │
│              │  - 路由任务                              │
│              │  - 错误处理                               │
│              └─────────────┘                            │
└─────────────────────────────────────────────────────────┘
```

### 3.2 Agent 类型对比

| Agent 类型 | 用途 | 特点 |
|-----------|------|------|
| `react.NewAgent` | 单 Agent + 工具 | 基础 ReAct 模式 |
| `adk.NewLoopAgent` | 多 Agent 循环 | 支持 Agent 间相互调用 |
| `adk.NewSequentialAgent` | 顺序执行 | 按顺序执行多个 Agent |
| `adk.NewParallelAgent` | 并行执行 | 同时执行多个 Agent |
| `Supervisor` | 监督者模式 | 一个 Agent 协调多个子 Agent |

### 3.3 SequentialAgent 顺序执行

```go
import "github.com/cloudwego/eino/adk/agent"

func NewSequentialAgent() (*agent.SequentialAgent, error) {
    // 创建各个 Agent
    researcher := createResearchAgent()
    writer := createWriterAgent()
    reviewer := createReviewerAgent()

    // 创建顺序 Agent
    seqAgent, err := agent.NewSequentialAgent(
        agent.WithAgents(
            "researcher", researcher,
            "writer", writer,
            "reviewer", reviewer,
        ),
        // 传递上下文
        agent.WithOutputMapping(map[string]string{
            "research_result": "topic",
            "draft": "content",
            "feedback": "revision_notes",
        }),
    )

    return seqAgent, nil
}

// 使用
func HandleRequest(ctx context.Context, topic string) (string, error) {
    result, err := seqAgent.Run(ctx, topic)
    return result, err
}
```

### 3.4 ParallelAgent 并行执行

```go
func NewParallelAgent() (*agent.ParallelAgent, error) {

```

### 3.5 LoopAgent 循环 Agent

```go
import "github.com/cloudwego/eino/adk/agent"

// LoopAgent 支持 Agent 之间的相互调用，形成循环
func NewLoopAgent() (*agent.LoopAgent, error) {
    // 创建主 Agent 和批评 Agent
    mainAgent := createMainAgent()      // 负责主要工作
    criticAgent := createCriticAgent()  // 负责批评和建议

    loopAgent, err := agent.NewLoopAgent(
        agent.WithMainAgent(mainAgent, "main"),
        agent.WithCriticAgent(criticAgent, "critic"),
        agent.WithMaxLoops(5),           // 最多循环 5 次
        agent.WithLoopPrompt("你是一个循环助手，完成任务后请调用 critic 进行评估"),
    )

    return loopAgent, nil
}

// 循环流程：
// 1. mainAgent 执行任务
// 2. criticAgent 评估结果
// 3. 如果不满意，返回反馈让 mainAgent 继续
// 4. 达到最大循环次数或满意时退出
```

## 4. Supervisor 监督者模式

### 4.1 Supervisor 概述

Supervisor 是一个"监督者"Agent，它使用 LLM 来：
- 理解用户任务
- 将任务分配给合适的子 Agent
- 收集子 Agent 的结果
- 整合响应返回给用户

### 4.2 架构图

```

│                      User Query                         │
└─────────────────────────┬───────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────┐
│                     Supervisor                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │  "我应该调用哪个/哪些 Agent 来处理这个请求？"      │   │
│  └─────────────────────────────────────────────────┘   │
│                          │                              │
│         ┌────────────────┼────────────────┐            │
│         │                │                │            │
│         ▼                ▼                ▼            │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐         │
│   │ Researcher│    │ Writer   │    │ Coder    │         │
│   └──────────┘    └──────────┘    └──────────┘         │
│         │                │                │            │
│         └────────────────┼────────────────┘            │
│                          │                              │
│                          ▼                              │
```

### 4.3 Supervisor 实现

```go
import (
    "github.com/cloudwego/eino/adk/prebuilt/supervisor"
    "github.com/cloudwego/eino/adk/agent"
)

type MyAgents struct {
    Researcher *agent.ReactAgent
    Writer     *agent.ReactAgent
    Coder      *agent.ReactAgent
}

func NewSupervisor(agents MyAgents) (*supervisor.Supervisor, error) {
    // 构建 Agent 映射
    subAgents := map[string]*agent.ReactAgent{
        "researcher": agents.Researcher,
        "writer":     agents.Writer,
        "coder":      agents.Coder,
    }

    // 配置 Supervisor
    sup, err := supervisor.NewSupervisor(
        ctx,
        &supervisor.AgentConfig{
            // 模型配置
            Model: chatModel,
            // 可用的子 Agent
            SubAgents: subAgents,
            // Supervisor 的系统提示
            SystemPrompt: `你是一个智能助手，可以调用以下子 Agent：
- researcher: 用于搜索和获取信息
- writer: 用于撰写内容
- coder: 用于编写代码

根据用户请求，选择合适的 Agent 来处理。`,
            // Agent 选择器（可选）
            AgentSelector: "researcher,writer,coder",
        },
    )

    return sup, nil
}

// 使用 Supervisor
func HandleUserQuery(ctx context.Context, query string) (string, error) {
    response, err := sup.Generate(ctx, query)
    return response, err
}
```

## 5. Plan-Execute-Replan 规划执行模式

### 5.1 模式概述

这是一种"先规划、后执行、再反思"的高级 Agent 模式：

1. **Plan（规划）**: 将复杂任务分解为多个步骤
2. **Execute（执行）**: 按顺序执行每个步骤
3. **Replan（反思）**: 检查结果，必要时重新规划

### 5.2 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                     User Task                               │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                       PLANNER                               │
│  "这个任务需要哪些步骤？顺序是什么？"                        │
│  ───────────────────────────────────────                    │
│  Step 1: 搜索相关信息                                        │
│  Step 2: 分析数据                                           │
│  Step 3: 撰写报告                                           │
└─────────────────────────┬───────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
          ▼               ▼               ▼
    ┌──────────┐   ┌──────────┐   ┌──────────┐
    │ Executor │   │ Executor │   │ Executor │
    │  Step 1   │──▶│  Step 2   │──▶│  Step 3   │
    └────┬─────┘   └────┬─────┘   └────┬─────┘
         │              │              │
         └──────────────┴──────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                       REPLANNER                             │
│  "执行结果符合预期吗？需要调整计划吗？"                      │
│  ───────────────────────────────────────                    │
│  ✓ 计划完成，任务成功                                       │
│  ✗ 需要重新规划某个步骤                                     │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                      Final Result                           │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 Plan-Execute-Replan 实现

```go
import "github.com/cloudwego/eino/adk/prebuilt/planexecute"

func NewPlanExecuteAgent() (*planexecute.PlanExecute, error) {
    // 1. 创建 Planner（规划器）
    planner, err := createPlanner()
    if err != nil {
        return nil, err
    }

    // 2. 创建 Executor（执行器）
    executor, err := createExecutor()
    if err != nil {
        return nil, err
    }

    // 3. 创建 Replanner（反思器）
    replanner, err := createReplanner()
    if err != nil {
        return nil, err
    }

    // 4. 组合
    peAgent, err := planexecute.NewPlanExecute(
        ctx,
        &planexecute.Config{
            Planner:   planner,
            Executor:  executor,
            Replanner: replanner,
            // 最大重试次数
            MaxRetries: 3,
        },
    )

    return peAgent, nil
}

// Planner 实现
func createPlanner() (*agent.ReactAgent, error) {
    return agent.NewReActAgent(
        ctx,
        &agent.Config{
            Model: chatModel,
            Tools: []tool.BaseTool{
                // 规划专用工具
            },
            SystemPrompt: `你是一个任务规划专家。
将用户请求分解为可执行的步骤。
每个步骤应该是一个具体的、可执行的任务。
以 JSON 格式输出步骤列表。`,
        },
    )
}

// Executor 实现
func createExecutor() (*agent.ReactAgent, error) {
    return agent.NewReActAgent(
        ctx,
        &agent.Config{
            Model: chatModel,
            Tools: []tool.BaseTool{
                // 执行所需工具（搜索、计算、文件操作等）
            },
            SystemPrompt: `你是一个任务执行专家。
严格按照给定的步骤执行任务。
记录每个步骤的执行结果。`,
        },
    )
}

// Replanner 实现
func createReplanner() (*agent.ReactAgent, error) {
    return agent.NewReActAgent(
        ctx,
        &agent.Config{
            Model: chatModel,
            SystemPrompt: `你是一个反思专家。
检查执行结果：
- 如果所有步骤都已完成，返回 "DONE"
- 如果需要调整某个步骤，返回更新后的计划`,
        },
    )
}
```

## 6. Retriever 检索器

### 6.1 Retriever 概述

Retriever 用于从外部知识库中检索相关信息，是 RAG（检索增强生成）系统的核心组件。

### 6.2 MultiQuery Retriever

MultiQuery 通过生成多个查询角度来提高召回率：

```go
import "github.com/cloudwego/eino/components/retriever"

// MultiQuery 工作原理：
// 1. 用户查询 "如何优化 Go 性能？"
// 2. LLM 生成多个变体：
//    - "Go 性能优化技巧"
//    - "提高 Go 程序效率的方法"
//    - "Go 语言最佳实践"
// 3. 并行执行所有查询
// 4. 合并去重结果
```

## 7. Interrupt & Checkpoint 中断与恢复

### 7.1 中断机制概述

Interrupt 允许在 Agent 执行过程中暂停，等待人类确认后再继续：

```
┌─────────────────────────────────────────────────────────────┐
│                        Agent 执行                            │
│                                                            │
│   Step 1 ──▶ Step 2 ──▶ Step 3 ──▶ [中断点]                  │
│                                        │                    │
│                                        ▼                    │
│                              ┌─────────────────┐           │
│                              │ 人类确认/修改    │           │
│                              │ - 批准继续      │           │
│                              │ - 修改参数      │           │
│                              │ - 取消操作      │           │
│                              └────────┬────────┘           │
│                                       │                    │
│         ┌─────────────────────────────┼──────────────────┐ │
│         │                             ▼                  │ │
│         │                    Step 4 ──▶ Step 5 ──▶ 完成   │ │
│         │                                                  │ │
│         │ (如果选择取消)                                    │ │
│         └──────────────────────────────────────────────►  │ │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 中断类型

## 8. 嵌套中断机制

### 8.1 嵌套中断概念

当 Agent 执行过程中发生中断，而此时还有未完成的子任务时，需要嵌套处理：

```
Level 0: 用户发起任务
    │
    ▼
Level 1: Agent 主流程开始
    │
    ├──▶ Step 1
    ├──▶ Step 2
    │
    ▼
Level 2: 子 Agent 执行
    │
    ├──▶ 子步骤 A
    ├──▶ 子步骤 B
    │
    ▼
Level 3: ⚠️ 嵌套中断触发
    │
    ├──▶ 需要批准的操作
    └──▶ 挂起整个执行链
```

### 8.2 嵌套中断处理策略

```go
// 嵌套中断处理
type NestedInterruptHandler struct {
    // 当前中断深度
    depth int
    // 每层的中断信息
    stack []InterruptInfo
}

type InterruptInfo struct {
    Depth    int
    AgentID  string
    Reason   error
    Context  map[string]any
    Approved bool
}

func (h *NestedInterruptHandler) HandleInterrupt(ctx context.Context, err error) error {
    // 1. 提取中断信息
    interruptInfo := extractInterruptInfo(err)

    // 2. 推入栈
    h.stack = append(h.stack, interruptInfo)
    h.depth++

    // 3. 等待人类处理
    for {
        approval := waitForHumanApproval(interruptInfo)
        if approval.Approved {
            break
        }

        // 用户拒绝，检查是否可以回退
        if h.depth > 1 {
            // 回退到上一层
            h.depth--
            h.stack = h.stack[:len(h.stack)-1]
            continue
        }

        return fmt.Errorf("任务被用户取消")
    }

    return nil
}

// 继续执行（处理完中断后）
func (h *NestedInterruptHandler) Resume(ctx context.Context) error {
    // 从栈顶恢复
    for len(h.stack) > 0 {
        top := h.stack[len(h.stack)-1]

        // 尝试恢复该层
        err := resumeAtLevel(top)
        if errors.Is(err, ErrNestedInterrupt) {
            // 该层还有待处理的中断，继续处理
            continue
        }

        // 该层恢复成功，弹出栈
        h.stack = h.stack[:len(h.stack)-1]
    }

    return nil
}
```

```go
}

func (r *multiQueryRetriever) Retrieve(ctx context.Context, query string, opts ...Option) ([]string, error) {
    // 1. 生成多个查询变体
    variants, err := r.generateQueryVariants(ctx, query)
    if err != nil {
        return nil, err
    }

    // 2. 并行检索
    results := make([][]string, len(variants))
    var wg sync.WaitGroup
    for i, v := range variants {
        wg.Add(1)
        go func(idx int, q string) {
            defer wg.Done()
            docs, _ := r.base.Retrieve(ctx, q)
            results[idx] = docs
        }(i, v)
    }
    wg.Wait()

    // 3. 合并去重
    return mergeAndDeduplicate(results), nil
}
```
