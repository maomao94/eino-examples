## 1. 入门问题

### Q1: 如何安装 Eino？

**问题**：首次使用 Eino，不知道如何安装

**解决方案**：

```bash
# 安装核心框架
go get github.com/cloudwego/eino@latest

# 安装扩展模块
go get github.com/cloudwego/eino-ext/...@latest

# 验证安装
go list github.com/cloudwego/eino
```

如果遇到网络问题，可以使用代理：

```bash
export GOPROXY=https://goproxy.cn,direct
go get github.com/cloudwego/eino@latest
```

### Q2: 第一个程序报 "module not found"？

**问题**：运行代码时报 `module not found`

**可能原因**：
- Go 模块未初始化
- 依赖未下载
- GOPATH 配置问题

**解决方案**：

```bash
# 1. 初始化 Go 模块
go mod init your-project-name

# 2. 下载依赖
go mod tidy

# 3. 确保 go.mod 包含正确的依赖
cat go.mod
```

如果仍然失败，检查 Go 版本：

```bash
go version  # 需要 1.21 或更高版本
```

## 2. 模型调用问题

### Q5: 模型调用超时怎么处理？

**问题**：调用 LLM 时经常超时

**可能原因**：
- 网络问题
- 请求过大
- 模型服务限流

**解决方案**：

```go
// 1. 设置超时
ctx, cancel := context.WithTimeout(ctx, 60*time.Second)
defer cancel()

result, err := model.Generate(ctx, messages)

// 2. 使用重试机制
withRetry := func(ctx context.Context, fn func() error) error {
    maxRetries := 3
    for i := 0; i < maxRetries; i++ {
        if err := fn(); err != nil {
            if strings.Contains(err.Error(), "timeout") {
                continue
            }
            return err
        }
        return nil
    }
    return fmt.Errorf("超过最大重试次数")
}
```

### Q6: 如何处理限流 (Rate Limit)？

**问题**：收到 `rate limit exceeded` 错误

**解决方案**：

```go
// 1. 使用指数退避重试
func withExponentialBackoff(ctx context.Context, fn func() error) error {
    baseDelay := time.Second
    maxDelay := 60 * time.Second

    for attempt := 0; ; attempt++ {
        err := fn()
        if err == nil {
            return nil
        }

        if !isRateLimitError(err) {
            return err
        }

        delay := baseDelay * time.Duration(1<<uint(attempt))
        if delay > maxDelay {
            delay = maxDelay
        }

        select {
        case <-time.After(delay):
        case <-ctx.Done():
            return ctx.Err()
        }
    }
}

func isRateLimitError(err error) bool {
    return strings.Contains(err.Error(), "rate limit")
}
```

## 3. 组件问题

### Q9: Tool 返回格式不正确？

**问题**：Agent 调用 Tool 时报错格式错误

**可能原因**：
- ToolInfo 的 Parameters 定义不完整
- 返回值不是字符串
- 参数类型不匹配

**解决方案**：

```go
// 正确示例
func (t *MyTool) Info() *agent.ToolInfo {
    return &agent.ToolInfo{
        Name:        "my_tool",
        Description: "工具描述",
        Parameters: map[string]interface{}{
            "type": "object",
            "properties": map[string]interface{}{
                "param1": map[string]interface{}{
                    "type":        "string",
                    "description": "参数描述",
                },
                "param2": map[string]interface{}{
                    "type":        "number",
                    "description": "数值参数",
                },
            },
            "required": []string{"param1"}, // 必填参数
        },
    }
}

// Invoke 必须返回 string 和 error
func (t *MyTool) Invoke(ctx context.Context, params map[string]any) (string, error) {
    param1, ok := params["param1"].(string)
    if !ok {
        return "", fmt.Errorf("param1 must be string")
    }
    return fmt.Sprintf("结果: %s", param1), nil
}
```

### Q12: Callback 没有被触发？

**问题**：注册了 Callback 但没有看到日志

**可能原因**：
- Context 未正确传递
- Handler 未实现所有方法
- Component 不支持 Callback

**解决方案**：

```go
// 确保正确传递 Context
ctx := callback.WithHandlers(context.Background(), handler)

// 传递到所有调用
result, err := agent.Run(ctx, input)     // ✓ 正确
result, err := agent.Run(context.Background(), input)  // ✗ 错误
```

## 4. 编排问题

### Q13: Graph 和 Workflow 怎么选？

**问题**：不知道该用 Graph 还是 Workflow

**选择建议**：

| 场景 | 推荐 | 理由 |
|------|------|------|
| 复杂 DAG 结构 | Graph | 更灵活的节点连接 |
| 简单线性流程 | Workflow | 声明式，更简洁 |
| 需要条件分支 | Graph | 支持复杂的条件判断 |
| 流式处理 | Workflow | 原生支持 Stream |

**Graph 示例**：
```go
g := compose.NewGraph[string, string]()
g.AddNode("a", nodeA)
g.AddNode("b", nodeB)
g.AddEdge("a", "b")  // 有向边
```

**Workflow 示例**：
```go
wf := compose.NewWorkflow[string, string]()
wf.Node("step1", nodeA).
   Node("step2", nodeB).
   Then()  // 顺序连接
```

### Q14: 如何处理分支逻辑？

**问题**：需要根据条件选择不同的执行路径

**解决方案**：

```go
// 使用条件节点
type RouterNode struct{}

func (n *RouterNode) Invoke(ctx context.Context, input string) (string, error) {
    // 根据输入决定路由
    if strings.Contains(input, "搜索") {
        return "search", nil
    } else if strings.Contains(input, "计算") {
        return "math", nil
    }
    return "default", nil
}

// 在 Graph 中使用
g.AddNode("router", routerNode)
g.AddConditionalEdge("router", map[string]string{
    "search":  "searchNode",
    "math":    "mathNode",
    "default": "defaultNode",
})
```

## 5. Agent 问题

### Q16: Agent 陷入无限循环？

**问题**：Agent 一直执行不停止

**可能原因**：
- Tool 设计问题（总是返回让 Agent 继续）
- 没有设置最大步数
- 循环条件判断错误

**解决方案**：

```go
// 1. 设置最大迭代次数
agent, err := react.NewAgent(ctx, &react.AgentConfig{
    Model:      model,
    Tools:      tools,
    MaxSteps:   10,  // 最大步数限制
})

// 2. 改进 Tool 设计
// 确保 Tool 在完成任务后返回明确的"完成"状态
// 而不是让 Agent 继续尝试

// 3. 添加停止条件
agent, err := react.NewAgent(ctx, &react.AgentConfig{
    Model:  model,
    Tools:  tools,
    StopFn: func(response string) bool {
        // 当响应包含特定内容时停止
        return strings.Contains(response, "[完成]") ||
               strings.Contains(response, "任务已完成")
    },
})
```

## 7. 部署问题

### Q22: 如何部署到生产环境？

**问题**：本地运行正常，部署后有问题

**检查清单**：

1. **环境变量**：确保 API Key 等配置正确
   ```bash
   # 生产环境使用更安全的方式管理密钥
   # 如 Kubernetes Secret, AWS Secrets Manager 等
   ```

2. **超时配置**：生产环境网络可能更慢
   ```go
   config := &openai.ChatModelConfig{
       Timeout: 120 * time.Second,  // 增加超时
   }
   ```

3. **重试机制**：生产环境需要更强的容错
   ```go
   withRetry(ctx, maxRetries=5, fn)
   ```

4. **监控告警**：添加指标收集
   ```go
   handler := &MetricsHandler{}
   ctx = callback.WithHandlers(ctx, handler)
   ```

5. **健康检查**：添加优雅关闭
   ```go
   srv := &http.Server{Addr: ":8080"}
   go srv.ListenAndServe()
   // 收到 SIGTERM 时优雅关闭
   ```

### Q23: 如何处理并发请求？

**问题**：多个用户同时请求时性能下降

**解决方案**：

```go
// 1. 使用 Worker Pool
pool :=.NewWorkerPool(func(ctx context.Context, req Request) Response {
    return processRequest(ctx, req)
}, 100)  // 100 个并发 worker

// 2. 使用 Semaphore 控制并发
sem := make(chan struct{}, 10)  // 最多 10 个并发
for _, req := range requests {
    sem <- struct{}{}
    go func(r Request) {
        defer func() { <-sem }()
        processRequest(ctx, r)
    }(req)
}

// 3. 限流保护
rateLimiter := tollbooth.NewLimiter(100, nil)  // 每秒 100 请求
```

### Q24: Checkpoint 如何实现高可用？

**问题**：需要确保 Checkpoint 不丢失

**解决方案**：

```go
// 使用 Redis 集群存储 Checkpoint
store, err := redis.NewCheckpointStore(ctx, &redis.Config{
    Addrs: []string{"redis-1:6379", "redis-2:6379", "redis-3:6379"},
})

// 添加备份策略
type BackupStore struct {
    primary   checkpoint.CheckPointStore
    secondary checkpoint.CheckPointStore
}

func (s *BackupStore) Save(ctx context.Context, cp *checkpoint.Checkpoint) error {
    // 同时写入主存储和备份存储
    if err := s.primary.Save(ctx, cp); err != nil {
        return err
    }
    go s.secondary.Save(ctx, cp)  // 异步备份
    return nil
}
```
