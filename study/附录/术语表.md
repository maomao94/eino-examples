## A

### ADK (Agent Development Kit)

**定义**：字节跳动开发的 Agent 开发框架，Eino 的上层应用框架。

**包含组件**：
- Runner：Agent 运行容器
- Supervisor：多 Agent 协调器
- Plan-Execute：规划执行模式

**相关文档**：[教程-ADK.md](../04-智能体/教程-ADK.md)

---

### Agent

**定义**：智能体，能够自主决策、执行任务、与环境交互的 AI 程序。

**核心能力**：
- 感知：接收输入
- 推理：分析理解
- 决策：选择行动
- 执行：调用工具

**相关文档**：[教程-基础Agent.md](../04-智能体/教程-基础Agent.md)

---

### APIKey

**定义**：用于身份验证的凭证字符串，用于访问 LLM 等服务。

**示例**：
```go
model, _ := openai.NewChatModel(ctx, &openai.ChatModelConfig{
    APIKey: "sk-xxxx",
})
```

---

### Approver / Approval

**定义**：审批者或审批机制，用于 Human-in-the-Loop 场景。

**相关文档**：[进阶-人机交互.md](../05-进阶/进阶-人机交互.md)

---

## B

### BatchNode

**定义**：批处理节点，用于并行处理多个输入。

**用途**：提高检索、计算等场景的吞吐量。

**相关文档**：[教程-批处理.md](../03-编排/教程-批处理.md)

---

### BM25

**定义**：一种基于关键词的检索算法，是传统文本检索的基础方法。

**特点**：
- 不依赖向量
- 速度快
- 可作为混合检索的一部分

---

### Buffer Memory

**定义**：基于固定大小的环形缓冲区实现的对话记忆。

**特点**：
- 固定容量
- 先进先出
- 内存占用可控

---

## C

### Callback

**定义**：回调机制，在关键节点执行的钩子函数，用于监控、日志、调试等。

**常用 Hook**：
- OnStart：开始执行
- OnEnd：结束执行
- OnError：发生错误

**相关文档**：[教程-回调.md](../02-组件/教程-回调.md)

---

### Chain

**定义**：链式调用，将多个组件串联执行的模式。

**示例**：
```
Input → Node1 → Node2 → Node3 → Output
```

**相关文档**：[教程-编排.md](../03-编排/教程-编排.md)

---

### ChatModel

**定义**：对话模型接口，用于生成对话回复。

**核心方法**：
- Generate：生成回复
- Stream：流式生成

**相关文档**：[教程-模型.md](../02-组件/教程-模型.md)

---

### Checkpoint

**定义**：检查点，用于保存 Agent 执行状态，支持中断后恢复。

**用途**：
- 人机交互中断恢复
- 故障恢复
- 状态持久化

**相关文档**：[进阶-人机交互.md](../05-进阶/进阶-人机交互.md)

---

### Chunk / Chunking

**定义**：
- Chunk：文本分块，RAG 中将长文档切分的单元
- Chunking：分块策略，将文档切分为小块的过程

**常用策略**：
- 固定大小分块
- 段落分块
- 层次分块

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

### Cohere

**定义**：加拿大 AI 公司，提供 Embedding 和 LLM 服务。

**产品**：
- Embed（多语言 Embedding）
- Command（LLM）
- Rerank（重排序）

---

### Completion

**定义**：补全，LLM 根据输入生成输出的过程。

**类型**：
- Text Completion：文本补全
- Chat Completion：对话补全

---

### Compose

**定义**：Eino 的编排模块，用于组合多个组件构建复杂应用。

**主要功能**：
- Graph：DAG 编排
- Workflow：工作流编排
- Chain：链式编排

**相关文档**：[教程-编排.md](../03-编排/教程-编排.md)

---

### Context Window

**定义**：上下文窗口，模型能够处理的最大输入+输出长度。

**常见限制**：
- GPT-4o：128K tokens
- Claude 3.5：200K tokens

---

### Contextual Retrieval

**定义**：上下文检索，融入上下文的检索方法，提高检索准确性。

---

## D

### DAG (Directed Acyclic Graph)

**定义**：有向无环图，Graph 编排的数据结构基础。

**特点**：
- 有方向
- 无循环
- 适合表达依赖关系

**相关文档**：[教程-编排.md](../03-编排/教程-编排.md)

---

### Deer-Go

**定义**：一种复杂多 Agent 协作模式，包含导航者、路由器、工作者等角色。

**适用场景**：复杂推理任务

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

### Deep Agent

**定义**：深度 Agent，支持多层递归分解和执行的 Agent 模式。

**与 Plan-Execute 的区别**：支持树状多层分解

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

### Dimension (向量维度)

**定义**：Embedding 向量的长度，常见维度有 768、1024、1536、3072 等。

**选择建议**：
- 越高维：越精确，占用越多内存
- 越低维：越快，占用越少内存，可能损失精度

---

## E

### Embedder / Embedding

**定义**：
- Embedder：Embedding 模型接口
- Embedding：将文本转换为向量的技术

**核心方法**：
```go
type Embedder interface {
    EmbedStrings(ctx context.Context, texts []string) ([][]float32, error)
}
```

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

### Eino

**定义**：字节跳动开发的 AI 应用开发框架，基于 Go 语言。

**核心模块**：
- ADK：Agent 开发套件
- Compose：组件编排
- Components：基础组件

---

### Ensemble Retriever

**定义**：集成检索器，融合多个检索器结果的检索策略。

**常用融合方法**：
- RRF（Reciprocal Rank Fusion）
- 加权平均

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

## F

### Flow

**定义**：Eino 的流式编排模块，与 Stream 相关。

**相关文档**：[教程-流编排.md](../03-编排/教程-流编排.md)

---

## G

### Generation / Generator

**定义**：生成，LLM 根据输入创建输出的过程。

**相关类型**：
- Text Generation
- Code Generation
- Image Generation

---

### Graph

**定义**：图，Eino 中基于 DAG 的编排方式。

**核心概念**：
- Node：节点
- Edge：边
- Compile：编译
- Invoke：执行

**相关文档**：[教程-编排.md](../03-编排/教程-编排.md)

---

## H

### HitL / Human-in-the-Loop

**定义**：人机交互，一种将人类决策融入 AI 流程的设计模式。

**典型场景**：
- 审批流程
- 异常处理
- 知识验证

**相关文档**：[进阶-人机交互.md](../05-进阶/进阶-人机交互.md)

---

### HNSW (Hierarchical Navigable Small World)

**定义**：一种高效的向量索引算法，用于加速相似度搜索。

**特点**：
- 高召回率
- 低延迟
- 内存占用较高

---

## I

### Interrupt / Interruption

**定义**：中断，Agent 执行过程中暂停等待人类决策的机制。

**相关文档**：[进阶-人机交互.md](../05-进阶/进阶-人机交互.md)

---

### Invoke / Invocation

**定义**：调用，执行组件或工具的动作。

**示例**：
```go
result, err := tool.Invoke(ctx, params)
```

---

## L

### LLM (Large Language Model)

**定义**：大语言模型，能够理解和生成人类语言的 AI 模型。

**代表模型**：
- GPT-4o, GPT-4o-mini (OpenAI)
- Claude 3.5 (Anthropic)
- Llama 3 (Meta)

---

### Loop Agent

**定义**：循环 Agent，支持迭代执行的 Agent 模式。

**典型用途**：反思改进、多次优化

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

## M

### Memory

**定义**：记忆，用于存储和管理对话历史的组件。

**类型**：
- Buffer Memory：固定容量缓冲
- Sliding Window Memory：滑动窗口
- Summary Memory：摘要记忆

**相关文档**：[教程-内存.md](../02-组件/教程-内存.md)

---

### Message

**定义**：消息，对话中的基本单元。

**类型**：
- UserMessage：用户消息
- AssistantMessage：助手消息
- SystemMessage：系统消息

---

### Middleware

**定义**：中间件，扩展组件功能的插件机制。

**常见用途**：
- 日志记录
- 指标收集
- 错误处理

---

### Multi-Agent

**定义**：多 Agent 系统，多个 Agent 协同工作的架构。

**模式**：
- Sequential：顺序执行
- Parallel：并行执行
- Supervisor：监督者模式
- Plan-Execute：规划执行

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

## N

### Node

**定义**：节点，Graph 或 Workflow 中的基本处理单元。

**类型**：
- ChatModelNode：模型节点
- RetrieverNode：检索节点
- LambdaNode：函数节点

---

## O

### Ollama

**定义**：本地 LLM 运行框架，支持在本地运行各种开源模型。

**特点**：
- 开源免费
- 支持多种模型
- 适合开发和测试

**使用方式**：
```bash
ollama serve
ollama pull llama3
```

---

### OutputKey

**定义**：输出键，用于在 Sequential Agent 中传递数据的键名。

---

## P

### Parallel Agent

**定义**：并行 Agent，多个子 Agent 同时执行的模式。

**用途**：
- 独立任务并行
- 收集多角度信息

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

### Parser / Parsing

**定义**：解析器，解析 LLM 输出为结构化数据的组件。

**常见用途**：
- JSON 解析
- 工具调用解析
- 意图识别

---

### Pinecone

**定义**：云端向量数据库服务，适合大规模生产部署。

**特点**：
- 全托管
- 全球分布
- 高可用

---

### Plan-Execute

**定义**：规划执行模式，包含 Planner、Executor、Replanner 的多阶段模式。

**流程**：规划 → 执行 → 检查 → 反思/重规划

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

### Prompt

**定义**：提示词，引导 LLM 输出的文本。

**类型**：
- System Prompt：系统提示
- User Prompt：用户提示
- Few-shot Prompt：少样本提示

---

## Q

### Query

**定义**：查询，用户的问题或请求。

**相关概念**：
- Query Understanding：查询理解
- Query Expansion：查询扩展

---

## R

### RAG (Retrieval-Augmented Generation)

**定义**：检索增强生成，结合检索和生成的 AI 架构。

**流程**：检索 → 上下文 → 生成

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

### ReAct (Reasoning + Acting)

**定义**：推理-行动模式，Agent 的一种核心实现方式。

**循环**：思考 → 行动 → 观察 → 思考...

**相关文档**：[教程-基础Agent.md](../04-智能体/教程-基础Agent.md)

---

### Retriever

**定义**：检索器，从知识库检索相关内容的组件。

**类型**：
- VectorRetriever：向量检索
- MultiQuery Retriever：多查询检索
- Ensemble Retriever：集成检索

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

### Runner

**定义**：运行器，ADK 中 Agent 的执行容器。

**职责**：
- 管理生命周期
- 处理输入输出
- 支持中断恢复

**相关文档**：[教程-ADK.md](../04-智能体/教程-ADK.md)

---

## S

### Schema

**定义**：模式定义，数据结构的规格说明。

**用途**：
- Tool 参数定义
- API 接口定义

---

### Sequential Agent

**定义**：顺序 Agent，Agent 按顺序执行的模式。

**特点**：下游依赖上游输出

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

### Similarity

**定义**：相似度，衡量向量或文本相似程度的指标。

**常用计算**：
- Cosine Similarity：余弦相似度
- Dot Product：点积
- Euclidean Distance：欧氏距离

---

### Skill

**定义**：技能，Agent 的能力单元，定义 Agent 可以执行的操作。

**结构**：
- Name：名称
- Description：描述
- Parameters：参数

---

### Sliding Window Memory

**定义**：滑动窗口记忆，只保留最近 N 条消息的记忆。

**参数**：
- WindowSize：窗口大小
- 超出窗口的旧消息被丢弃

---

### Stream / Streaming

**定义**：流，支持实时输出的模式，边生成边返回。

**优势**：
- 降低感知延迟
- 支持逐字显示
- 提高用户体验

**相关文档**：[教程-流编排.md](../03-编排/教程-流编排.md)

---

### Supervisor

**定义**：监督者，协调多个子 Agent 的 Agent。

**职责**：
- 任务分配
- 结果聚合
- 流程协调

**相关文档**：[进阶-MultiAgent.md](../05-进阶/进阶-MultiAgent.md)

---

## T

### Temperature

**定义**：温度参数，控制 LLM 输出随机性的超参数。

**取值范围**：通常 0-2

**效果**：
- 低值（0-0.3）：更确定，更保守
- 中值（0.5-0.7）：平衡
- 高值（0.8-1）：更随机，更有创意

---

### Token

**定义**：Token，语言模型处理的最小文本单元。

**估算**：
- 1 Token ≈ 0.75 个英文单词
- 1 Token ≈ 1-2 个中文字符

---

### Tool

**定义**：工具，Agent 调用外部功能的接口。

**结构**：
- Info：工具元信息
- Invoke：执行方法

**相关文档**：[教程-工具.md](../02-组件/教程-工具.md)

---

### Tokenizer

**定义**：分词器，将文本分割为 Token 的工具。

**用途**：
- 计算 Token 数量
- 截断过长文本

---

### Transformer

**定义**：Transformer 架构，现代 LLM 的基础架构。

**核心组件**：
- Attention Mechanism
- Feed-Forward Network

---

## V

### Vector

**定义**：向量，Embedding 产生的数值数组。

**示例**：`[0.12, -0.34, 0.56, ...]`

---

### VectorStore

**定义**：向量数据库，存储和检索向量的数据库。

**代表产品**：
- Chroma（本地）
- Qdrant（自托管）
- Pinecone（云）
- Milvus（自托管/云）

**相关文档**：[教程-检索.md](../02-组件/教程-检索.md)

---

## W

### Workflow

**定义**：工作流，声明式的节点编排方式。

**特点**：
- 声明式
- 简洁易用
- 适合线性流程

**相关文档**：[教程-编排.md](../03-编排/教程-编排.md)
