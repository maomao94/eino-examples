## 1. Flow 概述

### 1.1 什么是 Flow

Flow 是构建在 compose 之上的高层抽象，专门用于 Agent 应用的开发。

```
┌─────────────────────────────────────────────────────────────┐

│                                                              │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              封装好的 Agent 组件                     │   │
│  │                                                      │   │
│  │   ┌─────────┐  ┌─────────┐  ┌─────────┐            │   │
│  │   │  ReAct  │  │Multi    │  │  Deer   │            │   │
│  │   │  Agent  │  │Agent    │  │  Go     │            │   │
│  │   └─────────┘  └─────────┘  └─────────┘            │   │
│  └─────────────────────────────────────────────────────┘   │
│                            │                               │
│                            ▼                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              Compose 底层编排                         │   │
```

## 2. Flow vs Compose

### 2.1 层级关系

```
┌────────────────────────────────────┐
│           Flow (高层 API)            │
│   ReAct Agent、Multi-Agent、DeerGo  │
├────────────────────────────────────┤
│         Compose (底层编排)           │
│      Graph、Workflow、BatchNode     │
├────────────────────────────────────┤
│       组件层 (Components)           │
│   Model、Tool、Retriever、Prompt   │
└────────────────────────────────────┘
```

### 2.2 使用场景对比

| 场景 | 推荐 | 原因 |
|------|------|------|
| 简单 LLM 调用 | Compose | 直接调用，不需要 Agent 能力 |
| 带工具的 Agent | Flow react | ReAct 循环，内置工具调用 |
| 多 Agent 协作 | Flow multiagent | Supervisor、Plan-Execute |
| 复杂 Agent 系统 | Flow deer-go | 完整的状态管理、计划执行 |

### 2.3 代码对比

```go
// Compose: 直接调用 Model
g := compose.NewGraph[string, *schema.Message]()
g.AddChatModelNode("model", chatModel)
g.AddEdge(compose.START, "model")
g.AddEdge("model", compose.END)
runnable, _ := g.Compile(ctx)
result, _ := runnable.Invoke(ctx, "你好")

// Flow: ReAct Agent
agent, _ := react.NewAgent(ctx, &react.AgentConfig{
    ToolCallingModel: chatModel,
    ToolsConfig: compose.ToolsNodeConfig{
        Tools: []tool.BaseTool{myTool},
    },
})
stream, _ := agent.Stream(ctx, messages)
```

## 3. ReAct Agent

### 3.1 ReAct 原理

ReAct = Reasoning + Acting，让 Agent 通过"思考-行动-观察"的循环来完成任务：

```
┌─────────────────────────────────────────────────────────────┐
│                     ReAct 循环                               │
│                                                              │
│  ┌──────────┐                                               │
│  │  思考    │  "用户要查天气，我需要调用天气工具"             │
│  └────┬─────┘                                               │
│       ▼                                                     │
│  ┌──────────┐                                               │
│  │  行动    │  调用 get_weather(北京)                        │
│  └────┬─────┘                                               │
│       ▼                                                     │
│  ┌──────────┐                                               │
│  │  观察    │  获取到天气数据：晴，25度                      │
│  └────┬─────┘                                               │
│       │                                                     │
│       │  是否完成？                                          │
│       ├─ 是 ──▶ 返回答案                                    │
│       │                                                     │
│       └─ 否 ──▶ 继续思考                                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 基本使用

```go
import (
    "github.com/cloudwego/eino/flow/agent"
    "github.com/cloudwego/eino/flow/agent/react"
)

func main() {
    ctx := context.Background()

    // 1. 创建 ChatModel
    arkModel, _ := ark.NewChatModel(ctx, &ark.ChatModelConfig{
        APIKey: os.Getenv("ARK_API_KEY"),
        Model:  os.Getenv("ARK_MODEL_NAME"),
    })

    // 2. 准备工具
    restaurantTool := tools.GetRestaurantTool()
    dishTool := tools.GetDishTool()

    // 3. 创建 ReAct Agent
    rAgent, err := react.NewAgent(ctx, &react.AgentConfig{
        ToolCallingModel: arkModel,  // 必须支持工具调用的模型
        ToolsConfig: compose.ToolsNodeConfig{
            Tools: []tool.BaseTool{restaurantTool, dishTool},
        },
    })
    if err != nil {
        panic(err)
    }

    // 4. 流式调用
    sr, err := rAgent.Stream(ctx, []*schema.Message{
        {Role: schema.User, Content: "我在北京，给我推荐一些辣的菜"},
    })
    defer sr.Close()

    for {
        msg, err := sr.Recv()
        if err == io.EOF { break }
        fmt.Print(msg.Content)
    }
}
```

### 3.3 Agent 配置选项

```go
rAgent, err := react.NewAgent(ctx, &react.AgentConfig{
    ToolCallingModel: chatModel,
    ToolsConfig: compose.ToolsNodeConfig{
        Tools: []tool.BaseTool{...},
    },

    // 流式工具调用检查器
    // 用于某些模型不在第一次响应返回工具调用
    StreamToolCallChecker: customChecker,

    // 最大迭代次数
    MaxIterations: 30,
})
```

### 3.4 导出 Graph

Flow Agent 底层使用 compose Graph，可以导出查看：

```go
// 导出为 Graph 用于可视化
anyG, opts := rAgent.ExportGraph()

g := compose.NewGraph[[]*schema.Message, *schema.Message]()
g.AddGraphNode("react_agent", anyG, opts...)
g.AddEdge(compose.START, "react_agent")
g.AddEdge("react_agent", compose.END)

// 生成 Mermaid 图
gen := visualize.NewMermaidGenerator("output")
g.Compile(ctx,
    compose.WithGraphCompileCallbacks(gen),
)
```

## 4. Multi-Agent 多 Agent

### 4.1 Plan-Execute 多 Agent

Plan-Execute 模式包含三个角色：
- **Planner**: 将任务分解为步骤
- **Executor**: 执行每个步骤
- **Replanner**: 检查并调整计划

```go
type Config struct {
    PlannerModel        model.BaseChatModel
    PlannerSystemPrompt string

    ExecutorModel        model.ToolCallingChatModel
    ExecutorSystemPrompt string
    ToolsConfig          compose.ToolsNodeConfig

    ReviserModel        model.BaseChatModel
    ReviserSystemPrompt string

    MaxStep int
}

type PlanExecuteMultiAgent struct {
    runnable compose.Runnable[[]*schema.Message, *schema.Message]
}

// NewMultiAgent 创建多 Agent
func NewMultiAgent(ctx context.Context, config *Config) (*PlanExecuteMultiAgent, error) {
    // 1. 准备工具
    toolsNode, _ := compose.NewToolNode(ctx, &config.ToolsConfig)

    // 2. 创建 Graph
    graph := compose.NewGraph[[]*schema.Message, *schema.Message](
        compose.WithGenLocalState(func(ctx context.Context) *state {
            return &state{}
        }),
    )

    // 3. 添加 Planner 节点
    _ = graph.AddChatModelNode(nodeKeyPlanner, config.PlannerModel,
        compose.WithStatePreHandler(modelPreHandle(config.PlannerSystemPrompt, true)),
    )

    // 4. 添加 Executor 节点
    _ = graph.AddChatModelNode(nodeKeyExecutor, config.ExecutorModel,
        compose.WithStatePreHandler(modelPreHandle(config.ExecutorSystemPrompt, false)),
    )

    // 5. 添加 Reviser 节点
    _ = graph.AddChatModelNode(nodeKeyReviser, config.ReviserModel,
        compose.WithStatePreHandler(modelPreHandle(config.ReviserSystemPrompt, true)),
    )

    // 6. 添加 Tools 节点
    _ = graph.AddToolsNode(nodeKeyTools, toolsNode)

    // 7. 添加转换节点
    _ = graph.AddLambdaNode(nodeKeyPlannerToList, compose.ToList[*schema.Message]())
    _ = graph.AddLambdaNode(nodeKeyExecutorToList, compose.ToList[*schema.Message]())
    _ = graph.AddLambdaNode(nodeKeyReviserToList, compose.ToList[*schema.Message]())

    // 8. 连接边
    _ = graph.AddEdge(compose.START, nodeKeyPlanner)
    _ = graph.AddEdge(nodeKeyPlanner, nodeKeyPlannerToList)
    _ = graph.AddEdge(nodeKeyPlannerToList, nodeKeyExecutor)

    // 9. Executor 条件分支
    _ = graph.AddBranch(nodeKeyExecutor, compose.NewGraphBranch(
        func(ctx context.Context, msg *schema.Message) (string, error) {
            if len(msg.ToolCalls) == 0 {
                return nodeKeyExecutorToList, nil
            }
            return nodeKeyTools, nil
        },
        map[string]bool{nodeKeyTools: true, nodeKeyExecutorToList: true},
    ))

    _ = graph.AddEdge(nodeKeyTools, nodeKeyExecutor)
    _ = graph.AddEdge(nodeKeyExecutorToList, nodeKeyReviser)

    // 10. Reviser 条件分支
    _ = graph.AddBranch(nodeKeyReviser, compose.NewStreamGraphBranch(
        reviserCondition,
        map[string]bool{nodeKeyReviserToList: true, compose.END: true},
    ))

    _ = graph.AddEdge(nodeKeyReviserToList, nodeKeyExecutor)

    // 11. 编译
    runnable, err := graph.Compile(ctx,
        compose.WithNodeTriggerMode(compose.AnyPredecessor), // 循环模式
        compose.WithMaxRunSteps(config.MaxStep),
    )

    return &PlanExecuteMultiAgent{runnable: runnable}, nil
}
```

### 4.2 节点关系图

```
START ──▶ Planner ──▶ [Plan] ──▶ Executor ──┬──▶ Tools ──▶ Executor
                                           │                        │
                                           └──▶ [无工具调用]          │
                                                                   ▼
                                                              Reviser
                                                                   │
                                                    ┌──────────────┴──────────────┐
                                                    │                             │
                                                    ▼                             ▼
                                                 END                         Executor
                                              (完成)                    (继续执行步骤)
```

### 4.3 使用示例

```go
agent, err := NewMultiAgent(ctx, &Config{
    PlannerModel: deepseekModel,
    PlannerSystemPrompt: prompt.DefaultPlannerPrompt,

    ExecutorModel: arkModel,
    ExecutorSystemPrompt: prompt.DefaultExecutorPrompt,
    ToolsConfig: compose.ToolsNodeConfig{
        Tools: []tool.BaseTool{searchTool, calculatorTool},
    },

    ReviserModel: deepseekModel,
    ReviserSystemPrompt: prompt.DefaultReviserPrompt,

    MaxStep: 100,
})

// 调用
result, err := agent.Generate(ctx, []*schema.Message{
    {Role: schema.User, Content: "帮我规划北京三日游"},
})
```

## 5. Deer-Go 项目结构

```

│   ├── model/        # 数据模型
│   │   ├── state.go  # 状态定义

│   ├── eino/        # Eino Agent 实现
│   │   ├── planner.go    # 规划器

│   │   ├── coder.go       # 程序员
```

### 5.3 核心状态

```go
// State 定义 Agent 的运行时状态
type State struct {
    // 用户原始请求
    Req string

    // 当前计划
    Plan *Plan

    // 已完成步骤
    CompletedSteps []StepResult

    // 当前步骤索引
    CurrentStep int

    // 研究员收集的信息
    ResearchResults []ResearchResult

    // 代码片段
    CodeSnippets []string

    // 最终报告
    FinalReport string
}
```

### 5.4 Agent 协调器

```go
// Coordinator 协调多个专业 Agent
type Coordinator struct {
    planner    *Planner
    researcher *Researcher
    coder      *Coder
    reporter   *Reporter
}

// 协调流程
func (c *Coordinator) Run(ctx context.Context, req string) (string, error) {
    // 1. 规划
    plan, err := c.planner.CreatePlan(ctx, req)
    if err != nil {
        return "", err
    }

    // 2. 执行每一步
    for _, step := range plan.Steps {
        result, err := c.executeStep(ctx, step)
        if err != nil {
            // 可以选择重试或调整计划
            continue
        }
        state.CompletedSteps = append(state.CompletedSteps, result)
    }

    // 3. 生成报告
    return c.reporter.Generate(ctx, state)
}
```

## 7. Callback 回调

### 7.1 Callback 机制

Callback 用于监控 Agent 执行过程：

```go
type MyCallback struct {
    callbacks.HandlerBuilder
}

func (cb *MyCallback) OnStart(ctx context.Context, info *callbacks.RunInfo, input callbacks.CallbackInput) context.Context {
    fmt.Printf("[开始] %s/%s\n", info.Component, info.Name)
    return ctx
}

func (cb *MyCallback) OnEnd(ctx context.Context, info *callbacks.RunInfo, output callbacks.CallbackOutput) context.Context {
    fmt.Printf("[结束] %s/%s\n", info.Component, info.Name)
    return ctx
}

func (cb *MyCallback) OnError(ctx context.Context, info *callbacks.RunInfo, err error) context.Context {
    fmt.Printf("[错误] %s/%s: %v\n", info.Component, info.Name, err)
    return ctx
}

// 流式回调
func (cb *MyCallback) OnEndWithStreamOutput(ctx context.Context, info *callbacks.RunInfo,
    output *schema.StreamReader[callbacks.CallbackOutput],
) context.Context {
    go func() {
        defer output.Close()
        for {
            frame, err := output.Recv()
            if err == io.EOF { break }
            fmt.Printf("[流] %s: %v\n", info.Name, frame)
        }
    }()
    return ctx
}
```

### 7.2 使用回调

```go
// 在 Agent 调用时传入
opt := []agent.AgentOption{
    agent.WithComposeOptions(compose.WithCallbacks(&MyCallback{})),
}

sr, _ := agent.Stream(ctx, messages, opt...)
```

## 8. 实战示例

### 8.1 带内存的 Agent

```go
// 创建内存存储
memory := NewInMemoryMemory()

// Agent 配置
a, _ := react.NewAgent(ctx, &react.AgentConfig{
    ToolCallingModel: chatModel,
    ToolsConfig: compose.ToolsNodeConfig{
        Tools: []tool.BaseTool{myTools...},
    },
})

// 调用时传入历史
messages := []*schema.Message{
    {Role: schema.User, Content: "你好"},
}
messages = append(messages, history...)
messages = append(messages, &schema.Message{Role: schema.User, Content: "我刚才说什么了？"})

sr, _ := a.Stream(ctx, messages)

// 保存到内存
for {
    msg, _ := sr.Recv()
    memory.Save(ctx, msg)
}
```

### 8.2 未知工具处理

```go

unknownHandler := func(ctx context.Context, toolName string) (string, error) {

a, _ := react.NewAgent(ctx, &react.AgentConfig{
    ToolCallingModel: chatModel,
```

### 8.3 动态工具选择

```go
// 根据上下文动态选择工具
dynamicTools := func(ctx context.Context, messages []*schema.Message) []tool.BaseTool {
    lastMsg := messages[len(messages)-1].Content

    var tools []tool.BaseTool
    if strings.Contains(lastMsg, "搜索") {
        tools = append(tools, searchTool)
    }
    if strings.Contains(lastMsg, "计算") {
        tools = append(tools, calculatorTool)
    }
    return tools
}
```
